## 一个单元怎样完成

总控冻结最小契约与验收清单 → 原开发一次交付固定SHA、结果和可执行步骤 → 原独立QA连续完成必要增量验收 → FAIL返原开发 / PASS进入正式门禁 → 已授权发布按AGENTS完成生产复验和清理 → 总控一次更新进度与下一步。

一名总控、一名开发、一名独立QA，不为准备、绑定、报告另建角色。信息和授权齐全时角色自主执行整个已限定阶段，不每个检查都交回总控。审批或外部输入是真实边界，不能绕过。

## 最小验收清单（写入当前契约或台账，不新增工具）

| 字段 | 必须说明 |
|---|---|
| 必验项 | 与本次差分直接关联的正常路径、缺陷反例、安全边界及预期结果 |
| 复用项 | 原件路径、适用SHA/环境、未受当前差分影响的理由；本地PASS不充当生产PASS |
| 不验项 | 未变行为、独立后续风险及缺材料的真实质量结论 |
| 操作范围 | 精确账号别名、合成资产、写入边界和清理/恢复标准 |
| 预算 | 准备和验收检查点；默认小修复15/30分钟，复杂单元说明差异；不超时标绿 |
| 完成条件 | 必验有证据、阻断FAIL已修、测试资产安全收尾、正式状态与报告一致 |

已有工具优先，小修复不自动建设通用测试系统。未变化的已通过检查不重跑；QA仍独立核验真实差分和关键反例。新非阻断风险进入后续候选，不自动启动下一轮“补验”。

## 状态与边界

正式状态：BACKLOG → SCOPED → DEV_ACTIVE → DEV_READY → QA_ACTIVE → QA_FAIL / QA_PASS → RELEASE_READY → DEPLOYED → PROD_VERIFIED → CLOSED。状态只能由正式CLI转换；registry是索引，不能覆盖`.pairvu-control`。计划更新用plan-sync，不删历史单元、不删除锁重建。

无发布授权的runtime止于RELEASE_READY；local_only独立PASS后可CLOSED。生产始终GitHub-first、fresh核验、同SHA部署。独立候选验收不可省略，但一次性文档/证据整理不触发应用构建、全量测试或额外QA任务。

总控持续wait/read回收，不以定时任务代替活跃工作；只报告实质进展、阻塞或所需用户动作。结束必须说明下一步、依赖及是否自动继续。用户改变优先级先安全清理已创建资产，保留PARTIAL和缺口，不能制造PASS。

任何角色都不得输出密钥、请求头或完整环境。必要凭据只在进程内按精确键加载；不伪造会话、付款、客户数据、人工标注或质量结果。生产、付款、客户外发和密钥操作遵守用户实际授权。
