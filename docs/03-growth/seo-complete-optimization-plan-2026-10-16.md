# Pairvu SEO 与转化完整优化方案

日期：2026-10-16
范围：自然搜索、内容体系、图片案例、站内转化、外链与分发、度量闭环。
当前基线：生产站已有 67 个 sitemap URL；六个存量页面与首个开放许可真实商品案例已在 2026-10-15 上线并通过独立 HTTP 验收。

## 1. 结论

附件方案的大方向正确：Pairvu 应围绕“AI 商品图生成或编辑后，商品本身是否被改坏”建设核心词、问题词、真实实测、外链与转化闭环。但其中的站点诊断已经过时，流量、DR、国家分布、关键词难度和 90 天增长目标没有当前一手数据支撑，不能直接作为执行依据。

当前最重要的工作不是批量新增页面，而是：

1. 取得最新 GSC、Bing、第一方漏斗、外链与 Core Web Vitals 基线；
2. 修复内容落地页到 checker、注册和付费的归因断点；
3. 用有明确使用权的真实商品图片持续做少量、可复现的实测；
4. 让真实案例反哺现有检查页、指南和场景页；
5. 以小批、相关、可记录结果的方式分发，按合格访问和检测完成衡量，而不是追逐 DR 或链接数量。

SEO 的核心增长单元应当是“一个真实问题 + 一组有权使用的素材 + 一次可复现编辑 + 一次冻结的 Pairvu 结果 + 人工复核 + 一个有上下文的案例页 + 一批相关分发”，而不是“一个关键词 + 一个模板页”。

## 2. 对附件方案的逐项判断

| 附件建议 | 当前事实 | 决策 |
| --- | --- | --- |
| 首页 H1 和正文太薄 | Title 已拥有 `AI product image checker`；Hero 有可见品类标签、H1、定位、说明、上传交互，页面已有 How it works、检查维度、市场说明、入口和 FAQ | 可以测试更明确的组合 H1，但不是“从零重建” |
| 建 5 个独立检查页 | 已有 Logo、标签文字、颜色、数量、组件、包装、可观察性 7 个页面 | 不建附件中的同义新 URL；会与现有页面冲突 |
| 首页增加 500 字以上 | 首页已包含实质内容；Google 没有 500 字门槛 | 只补能提高理解或转化的内容，不按字数填充 |
| 增加客户 Logo 墙和 Trusted by 占位 | 当前没有相应公开证据 | 禁止占位社会证明；有真实授权客户后再上 |
| Pairvu vs manual QC 对比 | 当前没有速度、准确率、成本对照研究 | 暂不做优劣表；可解释机器检查、人工决定和发布资格的职责分工 |
| Product Hunt、目录、社区批量外链 | 可以带来发现和首批用户，但链接属性、质量和流量不可预设 | 做小批试验并记录结果；不把平台 DR 或 dofollow 当交付 |
| 100 张研究报告 | 当前只有一个开放许可真实案例，真实质量样本仍缺 | 先做 3–5 个严谨案例；样本与标注成熟后再立项研究报告 |
| 首次检查“不存图”、3 秒或 10 秒出结果 | 匿名图片最长保留 24 小时；登录账户按套餐保留 7/30 天；首个真实案例耗时约 37 秒 | 不使用这些不实承诺；文案与实际保留和延迟一致 |
| 免费版 10 次、Pro 无限次和永久保留 | 免费版 10 次；付费方案为 150/600/1500 次且保留 30 天 | 保持真实套餐，不宣传无限或永久 |
| PDF 和团队分享作为注册门槛 | 当前主要是 CSV、批次、SKU、审核与发布工作台能力 | 不把未实现功能写进 CRO；另行验证需求再开发 |
| 90 天达到 DR 15–20、月访问 1000–2000 | 缺少可核实的当前基线、市场和转化率 | 改为基于 30/60/90 天真实窗口的方向性目标，不保证流量或 DR |

## 3. 定位、受众与搜索意图

### 3.1 定位

- 市场：AI product photography。
- 产品类别：AI product image checker。
- 核心任务：把批准的商品原图与 AI 生成、编辑或候选图进行参考图对比。
- 结果边界：Pairvu 检查可见商品证据；它不判断图片来源真伪，不修图，不认证商标，不保证平台批准，也不自动发布到电商平台。

### 3.2 首要受众

1. 使用 AI 制作商品图的品牌内容团队；
2. 同时交付多个 SKU 和版本的创意代理商；
3. 需要在 Amazon、Shopify 或自有站发布素材的电商运营；
4. 需要保留原图、审核决定和交付记录的商品摄影及后期团队。

首页保持市场级定位，不只写成电商工具。行业、平台和团队工作流由现有 use-case 页面承接。

### 3.3 关键词所有权

| 搜索意图 | 唯一承接页 | 处理原则 |
| --- | --- | --- |
| AI product image checker | `/` | 唯一工具页，不建 checker 同义 URL |
| AI product photography | `/ai-product-photography` | 市场教育与质量控制支柱页 |
| Logo、标签、颜色、数量、组件、包装、可观察性 | `/checks/*` 现有 7 页 | 每页拥有一个属性级任务 |
| 具体变更或真实测试 | `/examples/*` | 每页必须有独特素材和证据 |
| 保持一致、原图对比、发布前清单 | `/guides/*` | 承接可重复执行的方法 |
| 代理商、品牌、电商、Amazon、Shopify | `/use-cases/*` | 承接角色或平台工作流 |
| 商品品类 | `/categories/*` | 只有独特证据和工作流才扩展 |

KGR、KD 和第三方搜索量只作辅助。每条数据必须记录工具、市场、语言、设备范围和日期；已有页面开始获得曝光后，以 GSC 的查询到页面数据优先。

## 4. 站内结构与页面建设

### 4.1 首页

首页不需要重写成文章，应保持“工具先行、证据随后”。建议顺序：

1. Hero 和上传工具；
2. 三步操作与输入要求；
3. 六类检查及可观察性；
4. 首个真实案例的简短入口，明确结果是 REVIEW；
5. 单次、批次、SKU、人工审核、发布资格和 CSV 的工作流入口；
6. 适用团队；
7. FAQ、隐私与定价。

可测试 H1：`AI Product Image Checker: Did AI Change Your Product?`。这保留原有品牌问题，同时使 H1 直接表达品类。上线前先看最新 GSC 首页查询、CTR 与平均位置；若当前 H1 已获得相关点击，采用受控 A/B 或分期观察，不频繁改动。

禁止使用：虚构客户 Logo、`Trusted by` 占位、未经测量的准确率/节省时间、固定秒数、零存储、无限检查、永久保留、自动发布或平台认证。

### 4.2 现有页面

2026-10-15 已完成并上线的六页继续作为首批核心集群：

- 保持商品一致性指南；
- 原图与 AI 图对比指南；
- Logo 检查；
- 标签文字检查；
- 创意代理商场景；
- How Pairvu works。

后续优化由数据触发：有曝光无点击先改 title/description 与搜索答案；有点击无 checker start 改首屏和 CTA；有 checker start 无完成则排查输入说明、上传和运行阻力；没有曝光先检查索引、查询匹配、内链和内容独特性。

### 4.3 新 URL 门禁

新增页面必须同时满足：

- 有不同于全部已发布页面的具体用户任务；
- 有唯一主词和 owning URL；
- 有一手实测、产品行为或当前官方来源；
- 有现有父页面无法容纳的独特信息；
- Pairvu 今天确实支持所描述的检查；
- 有父页、两个相关页面和 checker 的正文内链；
- 有唯一 title、description、H1、canonical 和意图；
- 通过 SEO inventory、意图重叠审查和人工发布门禁。

不满足时合并进旧页、保持 noindex 草稿或拒绝创建。禁止按 Midjourney、ChatGPT、Photoroom 等工具名批量建页；只有完成该工具的真实、可披露测试后才允许一个工具专题。

## 5. 真实商品图片实测计划

### 5.1 素材权利

“流量大的产品图片”可以帮助选择品类，不能自动取得图片使用权。公开案例只使用：

- 创始人自有图片；
- 客户明确书面授权且允许公开的图片；
- 逐图核实许可的 Commons 或开放资源；
- 品牌官方明确允许再使用的 press kit；
- 与摄影师或品牌单独取得的许可。

不能因图片出现在 Google、Amazon、品牌官网或社交平台就下载并重新发布。品牌案例需标注商标归属、素材许可、非关联关系、测试日期和历史包装边界。

### 5.2 每个案例的最小记录

1. 原图来源、作者、许可、下载日期和文件摘要；
2. 编辑工具、版本、日期、精确提示词和输出数量；
3. 保留全部输出，不挑选最有利结果；
4. Pairvu 模型、prompt、engine、policy、延迟、成本和原始 JSON；
5. Logo、文字、颜色、数量、组件、包装、视角和可观察性逐项记录；
6. 机器结论、人类观察和发布决定分开；
7. 失败、误报、漏报和不可观察项照实保留；
8. 明确样本不能证明总体准确率。

### 5.3 首批主题

首批只增加 3–5 个案例，优先覆盖不同证据难点：

1. 小字/容量可读的护肤或饮料包装；
2. 泵头、瓶盖、喷头等关键组件；
3. 多件装数量或附带配件；
4. 反光、透明或金属包装导致的可观察性 REVIEW；
5. 同一 SKU 正常换背景的 hard-negative PASS。

每个案例先补强已有检查/指南，再判断是否需要独立 URL。不要为了“每周发文”制造薄页。

## 6. 技术 SEO 与图片发现

当前 canonical、robots、sitemap、metadata、结构化数据和 registry 基础已经存在。技术工作按实际证据推进：

1. 每周保存 GSC 页面索引、sitemap、抓取和增强结果；
2. 核对 67 个 URL 的索引状态，不把 HTTP 200 当作已索引；
3. 对首页、核心指南、检查页和真实案例取得真实 CWV/Lighthouse 基线；
4. 自动检查 broken links、canonical、单 H1、index/noindex、schema 与 sitemap 一致性；
5. 为真实案例使用可抓取的原图/候选图 URL、描述性文件名、alt、caption、尺寸和许可上下文；
6. 评估案例的 `Article`/`ImageObject` 是否与可见内容一致，不添加评分、评论或商品富结果伪标记；
7. 新增或更新图片时检查 Google 图片抓取与落地页索引，不单纯增加 image sitemap 复杂度；
8. 保持 `/api/` 禁止抓取、公共内容允许抓取；爬虫策略变更后做生产复核。

Google 建议帮助搜索引擎发现图片并优化图片落地页；它也强调原创信息、亲身经验和服务于真实读者的内容。规模化生成缺少独特价值的页面可能构成 scaled content abuse。依据：[people-first 内容](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[图片 SEO](https://developers.google.com/search/docs/appearance/google-images)、[垃圾内容政策](https://developers.google.com/search/docs/essentials/spam-policies)。

## 7. 转化与归因

### 7.1 当前主要缺口

首页 checker 已记录 `landing_view`、上传、开始、完成、失败、结果查看和反馈；UTM/referrer 也会进入第一方事件。但内容页普通 Link 不统一记录 `content_id`/`source_page`，从内容页进入首页后的落地归因可能丢失。`sessionAttribution` 当前放在 localStorage，也需要明确 TTL 或改为真正的 session 范围，避免旧来源长期归给新访问。

### 7.2 最小工程任务

- 所有 indexable 内容页记录一次 `content_landing_view`，properties 包含 route、family、content_id；
- 内容到 checker、案例到 checker、内容到 pricing 分别记录 CTA；
- 在站内跳转中保留 `source_page`/`content_id`，不在站内链接加入 UTM；
- 给 session attribution 增加明确过期或 sessionStorage 语义；
- 记录 signup completed、subscription activated/cancelled、check-pack completed 等服务端可信事件；
- 报表按首次来源、会话来源、落地页和内容 ID 展示，排除 test/unknown；
- 不尝试把匿名 GSC 查询逐个拼接到具体用户。

### 7.3 漏斗

按来源和落地页观察：

`content landing → checker CTA → checker started → 两图上传完成 → analysis completed → result viewed → signup → paid activation`

优化顺序由最大真实流失点决定。没有漏斗数据前，不先开发 PDF、团队分享、无限套餐或大规模首页改版。

## 8. 外链与分发

### 8.1 原则

- 外链来自可引用的真实案例、方法、清单或数据，不来自批量交换；
- 相关性、合格访问和实际使用高于 DR；
- 不购买排名链接、不做 PBN、不批量目录、不重复精确匹配锚文本；
- 付费 placement 按平台和搜索政策标记 sponsored/nofollow；
- 社区先回答问题，规则不允许推广时不带品牌或链接；
- 不用免费 Pro 换取必须好评或隐藏商业关系。

### 8.2 首批渠道

1. 创始人 LinkedIn：真实案例的一张对比图、一个发现、一个限制；
2. 商品摄影/创意代理商：提供可引用案例和发布前检查清单；
3. 电商品牌运营和独立创作者：邀请用其有权公开的素材做联合实测；
4. 与 AI 商品图工具的内容团队合作：共同说明生成与质量控制的职责边界；
5. Product Hunt：等首页、真实案例、演示素材、FAQ、隐私和首批反馈齐备后再作为产品发布活动；
6. 工具目录：只选仍活跃、相关、可带真实用户且信息可维护的少量目录。

首批交付限定为两份渠道稿、五个高相关对象候选和一个统一记录表。没有公开 URL 或真实联系结果不能记为已分发。任何实际发送、发布或联系人数据处理需单独授权。

## 9. 指标体系

### 9.1 北极星指标

`来自非品牌自然搜索或相关引用的、成功完成一次分析的合格新会话数`

它同时约束流量相关性和产品实际使用，优于只看访问、DR 或排名。

### 9.2 分层指标

| 层级 | 指标 |
| --- | --- |
| 抓取与索引 | sitemap 已发现/已索引、关键页最后抓取、索引原因、图片发现 |
| 搜索需求 | 非品牌 impressions、clicks、CTR、position、query→page、国家、设备 |
| 内容参与 | landing、checker CTA、案例深度、返回访问 |
| 产品激活 | checker start、两图上传、analysis completed、result viewed |
| 商业转化 | signup、付费激活、检查包、30 天复用；test/unknown 排除 |
| 分发 | 合格推荐访问、完成检测、回复/合作、真实引用页面 |
| 内容质量 | 索引后有无相关查询、是否产生使用、是否应改进/合并/noindex |

第三方 DR、KD 和估算流量仅为诊断信号，不作为主要目标。任何“从 191 到 2000”或“DR 3.5 到 20”的承诺都必须先取得同口径基线，否则删除。

## 10. 90 天执行路线

### 第 0–2 周：数据与转化地基

- 导出最新 GSC 28/90 天查询、页面、国家、设备、索引和 sitemap；
- 导出 Bing、第一方事件漏斗、当前外链和真实 CWV；
- 验证附件中的 DR、191 访问、印尼流量和两个关键词是否仍成立；
- 实现内容落地和 CTA 归因，修正 session attribution 生命周期；
- 根据数据决定是否测试组合 H1，并在首页加入真实案例入口；
- 不新建检查同义页。

完成标准：能回答“哪个查询进入哪个页面、多少人进入 checker、多少人完成检查、哪一步流失”。

### 第 3–6 周：真实证据集群

- 完成 3 个新增授权案例；
- 更新对应检查页、指南、品类页和案例 hub 的正文链接；
- 为案例补图片上下文、许可和分享素材；
- 每个案例单独验收来源、结果、边界和生产页面；
- 只在独特意图成立时新增 URL。

完成标准：至少覆盖一个 PASS、一个 FAIL、一个 REVIEW；每页都有实际过程和原始结果，不产生准确率结论。

### 第 4–8 周：小批分发

- 先发布两份自有渠道内容；
- 联系五个高相关合作对象；
- 选择少量有效目录或 Product Hunt 准备；
- 使用独立 campaign/content 标识，记录访问、checker start 和完成；
- 社区内容以解决问题为主，不复制同一推广帖。

完成标准：每次分发有公开 URL 或联系记录、关系披露、目标页和实际结果；没有结果的草稿不计完成。

### 第 7–12 周：数据复盘与扩展

- 用索引、查询和转化决定页面 keep / improve / consolidate / noindex；
- 把表现最好的案例扩成方法文章、合作测试或短视频；
- 只有样本、授权、双标和冻结留出集齐备时，才启动多样本研究报告；
- 根据真实调用方需求再决定 API/Webhook、PDF 或团队分享，不让 SEO 方案擅自扩大产品范围。

完成标准：形成第一份 30/60/90 天同口径报告，并给出下一轮最多三个有证据的优先事项。

## 11. 优先级任务清单

| P0 | 内容到 checker 的归因 | 现有事件系统 | route/family/content_id/CTA/完成检测可关联，test排除 |
