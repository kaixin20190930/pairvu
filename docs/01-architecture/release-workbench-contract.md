# UPG-06 release workbench contract

Developer scope: local implementation and DEV_READY evidence; independent acceptance binds the candidate Git SHA. No production release or feature enablement is authorized. RELEASE_WORKBENCH_ENABLED is exact-string true and defaults false in production config. No schema migration is necessary: workspace analysis, child, snapshot and review-head indexes already support the reads.

## Immutable rule and priority

release-policy-001 is a built-in manifest with canonical JSON SHA-256. Its exact supported versions are engine m0-qa-engine-008, risk m0-risk-policy-003, model policy m0-model-policy-002, OpenAI gpt-4.1-mini, prompt m0-real-mvp-009+regions-003, identity guard identity-evidence-004 and regions schema 1. Version changes require a new manifest version and code review. Clients cannot supply policy/version/actor/workspace overrides.

Priority: integrity/source/evidence failures, noncompleted analyses, unavailable images, explicit reject, high/critical issues => blocked. Otherwise absent approve (including revoke) => needs_review. Only complete supported evidence plus a current source-matching approve => eligible. All reasons remain visible, including limitations, original machine verdict and human revision. Eligibility is a current rule evaluation, never an external publication or historical mutation. PASS alone cannot release.

Completeness requires nonempty unique known selected checks; exactly one observation per selected check and no extras; bounded source (24 rows per child type, 64 KiB combined evidence/model usage, 1 KiB selected-check JSON, 32 KiB product snapshot, 256 KiB reviewed snapshot); all storage budgets count UTF-8 bytes through SQLite length(CAST(text AS BLOB)), including embedded NUL, with the exact boundary accepted and boundary+1 rejected; match/mismatch with observable reference and candidate, sufficient coverage, recognized confidence/difference kind, nonempty explanation, both observations, comparison summary and visible evidence; supported identity guard and comparable identity evidence for logo/text; well-formed asset-bound region pairs (unverified numeric regions are never treated as localization proof); at least one successful supported model call bound to both input assets; no limitations. Recomputed risk verdict and issue identities/severity/confidence must match the stored machine result. Unknown, malformed, missing, uncertain, not-observable and not-applicable evidence all fail closed. This deliberately conservative first rule does not interpret not-applicable as complete evidence. The current risk policy assigns high/critical to all product differences, so such REVIEW records cannot become eligible. Future valid complete REVIEW records are not rejected solely for their verdict, but require a separately reviewed supported policy version.

## Source, ownership and consistency

Only server sessions resolved by existing auth/account logic identify workspace/user. Every data read additionally requires active workspace owner membership. Anonymous requests return 401; inactive/foreign owners receive 404. List/export never accept client identities. Feature-off routes return 404 and navigation remains hidden. GETs do not write analyses or audit decisions. Detail links open the existing single-analysis review screen.

One SQL SELECT per bounded scan returns machine rows, ordered child records, review head/current event, asset metadata, frozen product snapshot and batch association from one SQLite read snapshot. No later per-row queries stitch revisions. Invalid head/event pairs or foreign child ownership fail closed. Current original machine data are mapped with the same read-only normalization as the review writer; their canonical semantic snapshot must equal the SHA-verified approved audit snapshot. A source changed after approval requires a new human decision. machineSourceHash additionally binds the original machine data, selected checks and input assets. If bounds or ownership prevent a complete materialization, sourceComplete=false and sourceHash=null; the blocked record explicitly carries a bounded diagnostic snapshot instead of claiming a full original hash. Actor IDs, request IDs, email and private notes are not exported. DB availability checks do not independently verify R2 object existence or image interpretation.

SKU/name/profile/reference versions come only from the frozen analysis snapshot, with original JSON SHA verification, normalized profile and identity/version binding validation against the owned immutable profile/reference rows. Product lifecycle/name fields are not used in eligibility. Current rename/archive is never joined into that identity. Unbound records explicitly have no frozen standard. Invalid or legacy-bound sources fail closed. Deleted/failed/expired/missing assets are unavailable and block release. Retention is evaluated by SQLite server time, not a client timestamp.

## Complete bounded traversal

Exact SKU (1–80 characters), productId/batchId (bounded safe identifiers), state all/pending_review/blocked/decided, limit 1–50 and opaque cursor are the only accepted parameters; duplicates/unknowns are rejected. pending_review means needs_review; blocked means blocked; decided means current approve or reject (may overlap blocked). Order is created_at DESC, id DESC. SQL applies workspace/frozen identity/batch constraints, then scans at most 100 source rows. Rule-state filtering can yield an empty page with a continuation. Cursor advances from the last consumed source row, never an arbitrary truncated match set. It is tied to server workspace and filters. scanWindowExhausted/scanned/hasMore/nextCursor explicitly describe boundaries; no guessed total. Following every continuation covers all matching records present in that ordering, including late matches after empty windows. Separate pages are evaluated at request time; concurrent inserts or decision changes do not constitute a frozen whole-workspace search session.

## Export

The actual existing active/trialing csvExportEnabled entitlement is required; free plans are denied. Export additionally requires explicit scope=page to acknowledge its bounded scan. Limit remains 1–50 and scan 100; headers expose row count, has-more, cursor and scan boundary. The CSV includes machine original versions/status/verdict/source snapshot/hash, current action/category/reason/revision/review machine hash, rule version/hash/eligibility/reason codes/evaluatedAt, original frozen product JSON/hash/version fields and batch ID. It excludes actor/private notes. Pages containing sourceComplete=false are rejected with export_source_incomplete (409), rather than silently exporting partial original evidence. UI export is explicitly one bounded search page, not all workspace results; following cursors exports remaining pages. Concurrent review writes return wholly before or wholly after a committed decision, never a mixed row. Every CSV cell is quoted; formula-looking prefixes after Unicode normalization/leading whitespace/control or leading tab/newline receive a literal apostrophe. Quotes/newlines are escaped without interpreting user data. Existing batch CSV uses the same safety helper.

## Validation limits

Evidence uses synthetic owned users/assets/model records in actual local D1 with all production migrations and actual routes/repositories, and actual React components in desktop/narrow browsers. No remote DB, real auth session, R2, model, payment or external publication is tested or invoked. Independent fixed-SHA QA remains required. Production, deployment and enablement remain separate future gates.
